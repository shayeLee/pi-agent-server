## 目标

在不扩大既有架构的前提下，复用现有链路完成“多轮讨论 → 方案确认 → 生成真实 Vue + onev-ui 原型”。不重新设计宿主通用事件系统，不新增复杂任务平台、版本化方案平台或发布供应链；现有能力足够时直接复用。

## 三项改动任务清单

### 1. 确定需求的流程

- [x] `interactive-prototype` 默认使用现有同一会话进行多轮文字和图片讨论；移除前端在该模式下的图片禁用，不再每条消息都触发原型生成。
- [x] 仅该模式显示“生成原型方案”。点击后由应用提交 `PREPARE_PROTOTYPE_PLAN`，基于当前会话整理目标、页面/组件、布局、交互、状态反馈、图片用途及必要假设。
- [x] 信息有缺口时继续追问；完整时在会话中显示待确认的完整方案卡片，不直接生成。
- [x] 用户在卡片点击“开始生成需求原型”后，由应用提交 `CONFIRM_PROTOTYPE_GENERATION`，再调用现有生成链路；生成输入使用该次已确认的会话上下文与方案。
- [x] 用户只在文本中请求“整理方案”“开始生成”等操作时，回复并提示点击对应按钮，不直接执行应用动作。
- [x] 确认后若用户修改需求，则更新方案并要求重新确认；按钮重复点击、过期卡片和旧方案仅做必要校验，优先复用现有请求幂等、状态与错误处理能力。
- [x] 历史会话恢复继续沿用现有机制，并能正确展示讨论、方案卡片、确认结果和已生成预览。

- [x] 将当前 renderer 的原生控件模拟替换为真实 Vue + onev-ui 组件；模型描述组件、布局、内容、交互和状态反馈，不输出仿制已有组件的实现。
- [x] 设计原型时，查阅并遵循所用组件已有的设计规范文件；未找到规范时，不臆造规范要求。
- [x] 不仿制 onev-ui 已有组件，不修改组件自有样式；实施前按现有组件和主题确认首批实际必需范围。

- [x] 插件负责校验模型结果、组织真实组件运行时，并复用现有保存与预览能力；仅在真实 runtime 必需时适配 CSP，不能放宽现有安全边界。
- [x] `onev` 侧提供现有组件能力并完成界面按钮、卡片和真实原型展示；`pi-agent-capability-onev` 侧承担 onev 业务编排与 renderer 适配；`pi-agent-server` 仅在现有通用会话/图片/调用能力不足时做最小适配，不预设必须修改宿主。

## 验证与边界

- [x] 前端测试 601 项通过；能力侧 469 项中 467 项通过，2 项原有显式外部工具测试跳过，0 失败。
- [x] 跨仓真实浏览器测试通过：onev Vue runtime 使用真实 `Button`/`Input`/`Table`/`Form`，覆盖输入、`navigate back`、`references`；CSP 无违规、无外部请求。
- [x] 旧原型真实 fixture 兼容；既有 DSL/HTML 产物仍可打开、保存与预览。
- [x] 生成指令要求先读取现有 `vue2-index search`/`component` 结果及组件规范，再生成原型。
- [x] 组件规范检索按需而非穷举：`PREPARE_INSTRUCTION` / `GENERATE_PREFIX` / `PROTOTYPE_GENERATION_INSTRUCTION` 只要求对不确定用法或规范的组件读取，明确禁止「对每个组件都读」与无关检索。原因：旧的穷举式强制读取把单次生成拖到 403 秒，触发前端超时（见 onev 侧 `docs/p8-copilot-evidence.md`）。
- [x] 生成轮次同时给出检索**下限**：`GENERATE_PREFIX` 与 `PROTOTYPE_GENERATION_INSTRUCTION` 要求「至少读取 1 个最不确定的组件规范」并把总检索次数控制在 8 次以内。原因：只给「按需」会让模型自认「没有不确定项」而一次都不查，导致误用组件 API（renderer 只校验语法与挂载调用，不校验组件名/props/事件）。
- [ ] 未以真实生产模型完成端到端验收，也未以真实生产模型验证所有组件均遵循规范；该验收待执行。

当前已知边界：light 主题动作仅有 `navigate`/`back`；原型为真实组件运行时展示，不连接真实业务后端。
